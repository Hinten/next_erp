## Corrections to apply to the caps row / master plan

**REFUTED — fix before the row hardens**

1. **`tokens`** — refresh_token is not simply "per shop_id / 30 days": store and refresh a pair per **shop_id / merchant_id / user_id / supplier_id** independently, and treat 30 days as an upper bound capped by the seller-chosen authorization validity (as low as **7 days**). **Do not key re-auth on `error_shop_refresh_token`** — the spent-token error is undocumented; the observed example is `error_auth`, and merchant/supplier variants reuse one name. Assume a concurrent double-refresh permanently loses a token pair (no refresh-token grace is documented). Never retry `shop_banned` / `shop_access_expired` / `shop_no_linked` as token problems.
2. **`push-ack`** — retry schedule is **per push type, not global**. Do not encode 300/1800/10800 as one caps value: webchat is 1/2/3, FBS BR pushes are 60/300/1800 and 30/600/1800. The **unit and anchor are inferred, not documented** — mark that cell inferred or `desconhecido`. Also: `timeout` is an enumeration over today's 34 pushes, not a rule.
3. **`app-type`** — replace "immutable" with: the category cannot be edited on the app, but an approved developer-account conversion to ISV **automatically converts Seller In-house → ERP System**, which **removes Chat API and Webchat Push**. One-way; no documented reverse. Design decision: an ERP System app has **no console "Authorize" button** and must build the redirect URL itself — the app-type choice changes the OAuth entry flow, not just permissions.
4. **`prices-line-totals`** — record line-total-vs-unit as **CONFIRMED (subtotal) only for `get_escrow_detail.original_price`/`discounted_price`**, and **UNKNOWN for `get_order_detail.model_original_price`/`model_discounted_price`**. Do not resolve by analogy; settle it with a live order of quantity > 1. The bundle-deal 0 applies to `model_discounted_price` only, and its fallback is GetEscrowDetails.
5. **`payment`** — delete "no payment resource". A BR-specific per-order resource exists (`get_order_detail.payment_info`, NT 2025.001: processor CNPJ, card_brand, transaction_id, payment_amount — a LIST, so an order can have several payments), plus an 18-endpoint Payment module. `pay_time` is an **optional field** — its absence is not "unpaid", and `order_status === 'PAID'` never fires (no PAID member in the enum). Use `get_escrow_detail_batch` (≤50, 1–20 recommended) instead of per-order polling. Settlement for a BR local seller = `get_escrow_list` + `get_escrow_detail(_batch)`; the CB payout family does not apply, and the claim's `get_payout_detail` is superseded by `get_payout_info`. Never reimplement the escrow_amount formula — it differs between the single and batch pages.
6. **`labels`** — insert the missing step **`get_shipping_document_parameter`** into the flow and read `selectable_shipping_document_type`/`suggest_shipping_document_type` per package instead of hardcoding pdf/zip. `tracking_number` before `create_shipping_document` is the BR-integrated-channel case, not universal. Record the capability as **"Shopee-generated only, by BR policy"** — a policy constraint; the self-print mechanism exists platform-wide (`get_shipping_document_data_info`). Subscribe to the AWB push instead of polling the result.

Key on `logistics_channel_id`, never on the carrier string. If the team has a live observation, record it as a dated observation with shop_id and channel, not as documented behaviour.

A consumer that assumes original_price will write a foreign-currency number into the price mirror — branch on `update_field`. **HOLDS-but-caveat — these change a design decision**

10. **`pkce`** — always send `shop_id`/`main_account_id` on the token exchange despite every code sample omitting it; the exchange itself is HMAC-signed (partner_key + `state` are the PKCE substitutes).
11. **`sign`** — host selection is by **server location** among three production domains and is unconfirmed for BR (guide 740 designates no BR host); verify empirically before hardening. Do not hardcode a sandbox host from an API page's `test_url` — three of four sources disagree with it.
