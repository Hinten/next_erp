A concurrent `POST /api/freight/melhor-envio/comprar` can no longer buy and pay for a second label (#1677). The pedido's `freteInicial.printLabelId` anchor only made a SEQUENTIAL re-click safe; two concurrent requests both read "no label yet" and each paid for one, the anchor ended last-writer-wins and the other paid label was orphaned.

The route now holds an in-flight claim — an expiring, never-renewed lease at `pedidos/{pedidoId}/compraEtiqueta/current` (new admin-only handle `compraEtiquetaCollection` in `@delfrance/data/admin/collections`; default-deny, not in `ALL_DOMAINS`, no rules change). A second request while it is live answers `423 { code: 'ME_COMPRA_EM_ANDAMENTO', leaseExpiraEmMs }` before any Melhor Envio call (423, not 409, so an older browser tab shows the message instead of "reconecte a conta"). The anchor write is a compare-and-set against the claim, `checkout` and `generate` are fenced (the claim must still be ours, the request inside a 240 s paid window, and before checkout the anchor still the label being paid), and the final write only lands while the pedido is still anchored on the bought label — a label PAID but no longer linked to the pedido answers `412 { code: 'ME_ETIQUETA_DESVINCULADA', printLabelId, printUrl }`, never a 200. The claim is released on every exit except a paid step that failed in transit (its own timeout, a dropped connection, a gateway-class 5xx), whose outcome is unknown: it then expires after 360 s, and the answer is the same coded `504 ME_TIMEOUT` the browser already treats as "outcome unknown". A release that fails in Firestore is logged and never replaces the response. New refusals: `503 ME_COMPRA_INTERROMPIDA` (paid window closed) and `412 ME_FRETE_ALTERADO` (the anchor moved during the buy). The request body's `printLabelId` is now ignored — the anchor comes from the pedido only. `MelhorEnvioHttpError` and `MelhorEnvioNetworkError` gain an `operacao` field naming the call that failed (an API method, `'token'` for `/oauth/token`, or `null`), so a token refresh failing inside a paid step is never mistaken for the paid call itself.
